Anthropic 工程经理 Felix Rieseberg 结合自己参与 Claude.ai、Cowork 和 Claude Code Desktop 的经验，讨论 AI 时代如何重新校准人的野心。模型能力并非均匀提升：有些能力已经足以让使用者完成过去难以想象的事情，另一些方面仍有明显短板。关键差异不只是“谁更会用工具”，还在于谁更早意识到自己可以追求更大的目标。

作者把使用 AI 的野心分成四个维度：**速度、高度、深度和广度**。速度是更快完成同一任务，已经是常见用法；其余三种则要求改变目标、方法和视角，而不只是让模型更快地产出内容。

**高度：从完成眼前任务转向实现真正结果**

提高高度，意味着不只让模型完成指定步骤，而是把注意力放到任务背后的目标：目标是什么、为什么重要、接下来希望发生什么。作者曾从让 Claude 修复一个个崩溃问题，转向让它确保应用整体不再崩溃。后者要求的不只是写补丁，还要让模型能够获取崩溃报告、关联版本与 Git 提交，并操作 Windows、macOS 和 Linux 环境，独立复现问题、验证修复结果。

文章以季度业务复盘为例，展示如何逐步提高任务目标：先不要只更新幻灯片中的数字，而是让模型分析本季度业务发生了什么变化、原因是什么、应该如何应对；再让它找出最迫切的三个管理决策，研究可选方向及其利弊；进一步，则让模型设计一种可能优于季度演示文稿的复盘机制，并与原流程并行运行一个季度，检验它能否更早发现问题、帮助调整资金和人员配置。

这种方式特别适用于最终需要决策、而非只需提交一份文档的工作。它也可能推动流程重构，让模型围绕结果持续运行，而不必由人逐项拆解并派发任务。不过，高层级目标只有配套数据、工具、权限和验证机制才可执行；一句“去赚钱”目前还不能替代这些基础条件。

**深度：进入专业方法和原始证据，而非停留在表面答案**

在深度上更有野心，是要求模型采用该领域顶尖从业者真正使用的工具、方法和材料，并持续追问，直到产出不只是专业措辞，而是能带来新认识的工作。

继续以客户流失为例，作者建议不要满足于模型生成一张 Markdown 表格或复述“用户流失来自新手引导”之类的常见判断，而要推动它使用数据库和统计模型，读取原始日志、原始业务数据，并尝试反驳现有假设。之后还可以让它建立客户仿真模型，重现过去一年的情况，寻找尚未发现的早期流失信号，并在未见数据上验证预测能力。

具体做法包括：坚持使用专家级工具；设定看似不合理但可检验的高目标；要求模型从原始资料出发质疑既有结论；尝试产出新的、可验证的知识；引入模型之外的评价机制。作者特别强调，不应让模型单独评判自己的结果，最好建立一个能自动运行并快速反馈的外部验证工具。

文章给出一段可复用的提示思路：要求模型先指出顶尖专家会做而用户尚未提出的事情、他们会查看哪些原始材料、会用哪些具体方法和工具，以及由什么独立机制判断结果正确；然后再据此改写任务要求。重点是“做得更深入”，而不是无止境扩大工作规模。

**广度：借用其他领域的知识与团队结构**

在广度上更有野心，是把任务带到表面所属领域之外，调用过去因成本太高而不会使用的知识、工具和方法。多线程、多 Agent 和调度系统降低了组织这类跨领域协作的成本，但前提是引入真正相关的方法，而不是只给模型安排一组角色名称。

作者建议先把任务中的名词改写成动词，描述它实际要产生的效果。例如，季度复盘不只是“一份演示文稿”，而是“在 30 分钟内让忙碌的人相信一套因果解释，并在不确定情况下作出决策”。这样更容易发现任务可能需要分析师、记者、编辑、动效设计师，甚至专门寻找漏洞的红队、做空者或法务会计师。

但跨领域协作不能沦为角色扮演：模型模仿某类专家的语气，并不等于采用了他们的研究方法。更好的要求是让模型像做空者研究自己的持仓那样开展调查，而不是只写出做空者风格的评论。作者也提到，自己曾经没想到可以让 Claude 用 Blender 制作个人主页的 3D 场景，直到看到同事的作品才意识到这种可能；许多令人惊喜的成果，正来自跳出原有专业边界。

上述方法通常要求模型能操作电脑、安装软件并访问相关数据，连接方式可以是 MCP，也可以是其他工具。工具能力是把宏大目标变成可执行工作的条件之一。

**野心、自我效能感与“可能性边界”**

作者认为，人容易受自己对“什么可能”的判断限制，也往往只在熟悉的专业领域内相信自己的能力。心理学中的“自我效能感”描述了一个人对自身完成任务能力的信念；相关研究显示，具体而有难度的目标，往往比“尽力而为”的模糊要求带来更好的表现。

文章列举了几种扩展可能性边界的路径：相信困难目标可以完成并实际去尝试；看到他人成功后，意识到自己也可能做到；允许试错，不因担心失败而束缚行动。George Dantzig 曾把课堂上的两道未解难题误当作作业并成功求解；Roger Bannister 打破英里跑四分钟纪录后，其他跑者很快也相继做到；作者还借网球训练和 Linux 早期发展说明，过度紧张地追求完美，有时反而妨碍实际表现。

AI 能力每隔几周就可能跃升，因此个人和组织都需要不断重新评估自己的能力边界。作者的结论不是盲目把所有工作交给模型，而是：把目标设得更高，要求模型深入证据、调用跨领域方法，同时建立外部验证和必要的工作流程，让技术能力真正转化为更有价值的结果。
